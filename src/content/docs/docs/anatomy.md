## Файлы

```
game.json          метаданные: slug, название, игроки, языки, пресеты, правила, клиент
rules.md           текст правил (rules.<язык>.md для других языков)
logic/index.ts     логика на сервере: export default GamePlugin
client/            клиент для браузера (vite), его видит каждый игрок
tests/             тесты на vitest
```

Подробности — в [справочнике по `game.json`](/docs/reference/game-json/)
и [справочнике API](/docs/reference/api/readme/) (на английском).

## Решает сервер

Состояние игры меняется только в `logic/`, а `logic/` работает только на
сервере. Клиент отправляет ввод — один из ходов, которые предложил
сервер, — а сервер его применяет или отклоняет. Изменённым клиентом
сжульничать нельзя.

`legalMoves(state, playerId)` перечисляет все ходы, которые игрок может
сделать сейчас. Клиент строит интерфейс из этого списка, а `simulate`
играет случайными ходами из него, поэтому список должен быть полным и
точным.

## Тот же seed — тот же матч

Логика детерминирована и чиста: без `Math.random`, часов, сети и
изменяемого состояния на уровне модуля. Случайность — только через
помощники движка (`ctx.random*`) с seed. Тот же seed и те же ходы дают
тот же матч; `simulate` это проверяет.

## Клиент в песочнице

Клиент работает в изолированном iframe на отдельном домене **без доступа
к сети**: никаких fetch, CDN и внешних шрифтов — всё собирается в бандл.
Он видит только то, что положено видеть его игроку, и общается с
магазином через bridge (`@table-games-engine/game-kit/bridge`). Клиент
должен работать на экране телефона шириной 360 px.

## Пресеты

Пресет — именованная конфигурация матча (размер поля, варианты правил)
в `game.json`. Его объект `config` передаётся в `setup`; первый пресет —
по умолчанию. `simulate` и `check` проверяют все пресеты.
